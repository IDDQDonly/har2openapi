# Конвертер HAR в OpenAPI

[English](README.md) | **Русский**

## HAR Studio: локальный интерфейс

Проекты API, анализ нескольких HAR, проверка маршрутов, неизменяемые версии и
сравнение наблюдений между релизами. Всё работает на вашем компьютере.
Язык интерфейса выбирается переключателем **EN / RU** в шапке. Сообщения и
HTML-отчёты используют выбранный язык; данные трафика и названия проектов не переводятся.

```bash
uv sync --locked
uv run --locked python -m studio.web
```

Откройте **http://127.0.0.1:8765**. Доступен только локальный адрес; для другого порта
используйте `--port 8766`. Остановить сервер — `Ctrl+C`.

### Первый проект

1. Создайте проект, например «API магазина».
2. Выберите один или несколько HAR-файлов и загрузите их. Фоновая задача покажет
   прогресс и текущий файл, а затем автоматически откроет выбор доменов.
3. Отметьте нужные домены, исключив сторонние сервисы.
4. Посмотрите результат и предложения объединить маршруты с числовыми ID или UUID.
   Можно принять предложение, изменить имя параметра или оставить адреса отдельно.
5. Раскройте операцию: у каждого поля есть типы, частота появления и ссылка
   «Почему такой вывод?» на файл, номер HAR-записи (с 1) и замаскированный пример.
6. Назовите и сохраните версию. ZIP-экспорт содержит OpenAPI для каждого сервера,
   самостоятельный HTML-отчёт и `evidence.json` с полным набором наблюдений.

### Следующие импорты

- **Дополнить текущую версию** объединяет старые и новые наблюдения. Результат
  сохраняется отдельным снимком: исходная версия не изменяется.
- **Сравнить новую версию** анализирует только новые HAR и сопоставляет их с выбранной
  исходной версией. Объём старой выборки не увеличивает счётчики новой.
- Сохранённые решения о маршрутах применяются к новым ID. В черновике их можно
  пересмотреть. Сохранить можно и без принятия предложений: адреса останутся отдельными.
- Любые две сохранённые версии проекта доступны на экране «Сравнить версии».

Сравнение показывает новые/ненаблюдавшиеся операции, статусы, поля и изменения
наборов типов. Отсутствие в выборке **не считается доказанным удалением** или
несовместимостью контракта. Обе выборки сопоставляются с решениями о маршрутах новой
версии. При импорте для сравнения учитываются только выбранные домены; при сравнении
сохранённых версий — все домены этих снимков.

Сравнение показывает панели **До / После** с подсветкой типов полей и размерами
выборок. Если в исходной выборке не менее 10 запросов, а в новой — меньше половины,
появляется пояснение о меньшем объёме данных. Это подсказка для проверки, а не оценка
достоверности. Для сохранённых версий изменение можно отметить как **ожидаемое**,
добавить комментарий или вернуть на проверку. Отметки относятся к конкретной
упорядоченной паре версий и не меняют сами снимки.

### Управление рабочим пространством

- Откройте **Управление проектом**, чтобы переименовать или архивировать проект.
  Архивные проекты доступны во вкладке **Архив**; их версии можно просматривать
  и сравнивать. Для нового импорта верните проект из архива.
- Ненужный черновик можно удалить со страницы проекта или самого черновика.
  Для удаления требуется подтверждающий флажок; сохранённые версии не удаляются.
- В разделе **Резервные копии** скачайте сжатую копию `.json.gz` со всеми активными
  и архивными проектами, версиями, черновиками, решениями о маршрутах и комментариями
  к ожидаемым изменениям.
- Там же можно восстановить копию. Проверенные данные добавляются как **новые проекты**
  с новыми ID; существующие записи не перезаписываются. Связи между восстановленными
  версиями сохраняются. Повторное восстановление создаёт дополнительные копии.
  Лимит загрузки — 50 МБ, после распаковки — 200 МБ.
- В копию не входят исходные HAR, фоновые задачи и кэш отчётов. Выполняющийся импорт
  попадёт в копию только после создания черновика. Копия может содержать секреты
  из трафика: маскирование по-прежнему работает по именам полей.

### Попробовать на примере

В `examples/before.har` и `examples/after.har` — только синтетические данные.
Загрузите `before.har`, объедините `/users/{user_id}` и `/orders/{order_id}`,
сохраните «До релиза». Затем выберите «Сравнить новую версию» и загрузите `after.har`.
В отчёте появятся переход `total` с числа на строку, ответ 409 и ненаблюдавшийся `email`.
Маршрут `/users/me` останется отдельным.

### Данные и границы анализа

- Проекты, черновики, решения и снимки хранятся в `.har2openapi/workspace.sqlite3`
  (исключено из Git). Другой каталог: `--data-dir /path/to/workspace`.
  Для переносимой копии используйте раздел **Резервные копии** без остановки приложения
  либо остановите сервер и скопируйте весь каталог данных. Существующая база
  автоматически обновляется при запуске.
- HAR не сохраняются отдельными исходными файлами. В базе находятся наблюдения
  с маскированными примерами, схемами, именами исходных файлов и номерами записей.
  Маскирование по именам не удаляет все возможные секреты из текста и URL-путей.
- Счётчики основаны на уникальных записях: повторная загрузка идентичного файла
  не удваивает их. Разные файлы с пересекающимися запросами могут содержать повторы.
- Частота поля считается среди тел того же направления, MIME-типа и статуса ответа.
  Для поля массива считается присутствие хотя бы в одном элементе на запись.
  Например, email у одного из 100 пользователей в единственном ответе — это
  1 из 1 ответов, а не 100 из 100 пользователей. Таблица сгруппирована по телам,
  пути выглядят как users[].email; промежуточные объекты и массивы скрыты.
  Пустые контейнеры и смешанные типы остаются видимыми. Полные данные сохраняются.
  Частота не означает обязательность поля.
- Структуры объектов объединяются по свойствам, массивы — по элементам. Несовместимые
  типы представлены через `anyOf`. При экспорте из Studio одинаковые повторяющиеся
  схемы объектов выносятся в `components/schemas` и подключаются через `$ref`.
  Имена определяются стабильными хешами содержимого, примеры наблюдений сохраняются.
  UUID используется для предложений маршрутов. Поведение экспорта CLI не изменено.
- До 50 МБ на импорт, 10 000 записей в файле и 20 000 уникальных записей в снимке.
  Импорт и анализ отчётов выполняются фоновым обработчиком. Одновременно в очереди
  и работе может быть до четырёх задач; выполняется одна задача за раз. Прогресс
  конвертации HAR основан на числе обработанных записей, остальные этапы показывают
  приблизительный прогресс. Отчёты кэшируются в SQLite между открытиями страниц
  и перезапусками (до 100 отчётов). Изменения наблюдений или правил создают новый ключ кэша.
- Интерфейс рассчитан на одного пользователя и один запущенный сервер на рабочее
  пространство. Загруженные байты хранятся только для текущей задачи, а не для
  автоматического повтора. После прерывания процесса незавершённые задачи помечаются
  ошибкой; их нужно повторить. Ошибка указывает проблемный файл; неуспешный импорт
  не создаёт частичный черновик. Экспорт и восстановление выполняются в веб-запросе.
- Решения о маршрутах и версии сохраняются между запусками. После перезапуска сервера
  обновите открытые страницы перед отправкой форм.

### Структура

`har2openapi.py` — общая конвертация без привязки к интерфейсу;
`studio/analysis.py` — наблюдения, объединение схем и сравнение;
`studio/store.py` — миграции, SQLite, снимки и отметки изменений;
`studio/jobs.py` — очередь задач и сохраняемый кэш анализа;
`studio/backup.py` — чтение и проверка резервных копий с ограничением размера;
`studio/export.py` — общие модели OpenAPI;
`studio/i18n.py`, `studio/locales/` — переводы интерфейса;
`studio/web.py`, `studio/templates/`, `studio/static/` — веб-интерфейс.

## Конвертер командной строки

Преобразует записи HTTP Archive (HAR) в YAML спецификации OpenAPI 3.0.3.
Для каждого сочетания схемы, хоста и порта создаётся отдельный файл.

## Установка

Требуются Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Выполните из каталога проекта:

```bash
uv sync --locked
```

Файл `.python-version` выбирает Python 3.12. Зависимости описаны в `pyproject.toml`,
а их точные версии зафиксированы в `uv.lock`. При изменении зависимостей сохраняйте
оба файла в Git. Конвертер запускается как набор скриптов и не требует системы
сборки пакета. Для установки только рабочих зависимостей используйте
`uv sync --locked --no-dev`.

## Использование

```bash
uv run --locked python main.py capture.har -o output
uv run --locked python main.py capture.har --url-filter example.com --cookies sid --ignore-headers User-Agent,Cookie -o output
uv run --locked python main.py capture.har --url-filter '^https://api\.example\.com/.*' --sensitive-names credential,private_key
```

Для интерактивного ввода запустите без имени файла:

```bash
uv run --locked python main.py
```

| Аргумент | Назначение |
| --- | --- |
| `filename` | HAR-файл; если не указан, включается интерактивный режим |
| `--url-filter` | Точный домен с необязательным портом или регулярное выражение, начинающееся с `^` |
| `--cookies` | Имена сохраняемых cookies через запятую; по умолчанию — все |
| `--ignore-headers` | Имена исключаемых заголовков через запятую, без учёта регистра |
| `-o`, `--output-dir` | Каталог результата; создаётся при необходимости; по умолчанию — текущий |
| `--sensitive-names` | Дополнительные имена полей, параметров запроса или заголовков для маскирования |
| `--include-secrets` | Явно отключает маскирование примеров |

Имена файлов имеют вид `openapi_https_example.com.yaml` или
`openapi_https_example.com_8443.yaml`. Существующие файлы с теми же именами
перезаписываются. Если совпадений нет, выводится сообщение, новые файлы не создаются.
Ошибки входных данных или файлов возвращают код завершения 1, ошибки аргументов — 2.

## Особенности конвертации

- Запросы и ответы используют собственные MIME-типы. Для JSON и `+json` определяются
  схемы объектов, массивов, строк, логических значений, целых и дробных чисел,
  а также значений, допускающих `null`.
- Пустые объекты и массивы, `false`, `0`, пустые строки и JSON `null` сохраняются.
  Отсутствующие тела запросов не добавляются в спецификацию. Текст остаётся текстом.
- В параметрах запроса сохраняются пустые и повторяющиеся значения. Cookies
  дедуплицируются и записываются как параметры `in: cookie`. Игнорирование `Cookie`
  также исключает cookies из соответствующего списка HAR.
- Заголовки сопоставляются без учёта регистра. `Authorization`, `Proxy-Authorization`,
  `Accept`, `Content-Type`, `Host`, `Content-Length` и псевдозаголовки HTTP/2
  не добавляются как параметры заголовков. Схемы аутентификации пока не определяются.
- Повторные операции объединяют статусы ответов и MIME-типы тел. Различные
  наблюдаемые схемы тел собираются через `anyOf`; для каждого MIME-типа сохраняется
  последний пример. Для параметров используется первое наблюдаемое значение.
- По записям трафика нельзя установить обязательность полей, поэтому параметры,
  тела и свойства объектов не помечаются обязательными.
- Неизвестные или некорректные статусы HTTP обозначаются как `default`, а не
  подменяются на `200`. Для HEAD, 204 и 304 тело ответа не добавляется. Ответы
  в Base64 представлены схемой байтовой строки без закодированного примера.

## Маскирование секретов

По умолчанию маскируются все значения cookies и поля с распознанными секретными
именами в заголовках, параметрах запроса, JSON и телах форм с URL-кодированием.
Сопоставление имён не учитывает регистр, дефисы и подчёркивания. Распознаются
`authorization`, `password`, `passwd`, `secret`, `session`, `sessionid`, `sid`,
а также имена, оканчивающиеся на `token`, `apikey`, `secret` или `password`.
Дополнить этот набор можно через `--sensitive-names`.

Строковые секреты заменяются на `[REDACTED]`. Для остальных секретных значений
используются совместимые по типу пустые значения: `0`, `false`, `{}`, `[]` или `null`.
Учётные данные удаляются из адресов серверов; краткие описания операций не содержат
исходных URL или строк параметров запроса.

Это маскирование по именам, а не полная анонимизация: секреты в путях, произвольном
тексте, нераспознанных полях или значениях других заголовков могут сохраниться.
Некорректный JSON остаётся исходным текстом. Проверяйте созданные файлы перед передачей
другим людям. `--include-secrets` отключает маскирование примеров, но не восстанавливает
исключённые заголовки и учётные данные в URL.

## Использование из Python

```python
from har2openapi import har2openapi

converter = har2openapi(
    filename="capture.har",
    url_filter="example.com",  # также принимает список доменов
    cookie_filter=["sid"],
    ignore_headers=["User-Agent"],
    output_dir="output",
    mask_secrets=True,
    sensitive_names=["credential"],
)
files = converter.create_openapi()  # список объектов pathlib.Path
```

## Разработка и проверка

```bash
uv sync --locked
uv run --locked python -m pytest -q
uv run --locked openapi-spec-validator output/openapi_https_example.com.yaml
```

Тесты проверяют созданные документы через
[openapi-spec-validator](https://openapi-spec-validator.readthedocs.io/en/latest/python.html),
а примеры тел и параметров — через `openapi-schema-validator`. Также проверяются
командная строка и исправленные ранее ошибки. Эти пакеты и pytest относятся к
зависимостям разработки; конвертер использует PyYAML, а локальный веб-интерфейс — Flask.

```bash
uv add <package>
uv add --dev <development-package>
uv lock --upgrade
uv sync --locked
```

## Текущие ограничения

Для конвертера командной строки примеры из HAR описывают наблюдаемый трафик,
а не полный контракт API. Параметры пути, схемы аутентификации и обязательность полей
требуют ручной проверки. Тела multipart и HAR `postData.params` пока не преобразуются:
используется только записанное поле `text`. Бинарные тела ответов не декодируются.
URL со схемами, отличными от HTTP/HTTPS, и неподдерживаемые методы отклоняются.
Нестандартные расширения HAR могут требовать нормализации перед конвертацией.
